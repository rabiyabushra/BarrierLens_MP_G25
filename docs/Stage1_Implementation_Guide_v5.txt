2.4.1 Building the 3 Binary Targets — OR logic, not averaging
Unlike v4's inverted-average-then-median approach, this is simple: a woman has a barrier of a given type if she reported "big problem" on ANY of that category's questions. This matches the base paper's own definition (Section 2.1 of the approach document: "25% of women reported at least one" household barrier).
# src/preprocessing/target_builder.py
import pandas as pd
 
BARRIER_COLS = {
    'household': ['v467b', 'v467c', 'v467f'],   # permission, money, companion
    'logistic':  ['v467d', 'v467e'],             # distance, transport
    'facility':  ['v467g', 'v467h', 'v467i'],    # no female provider, no provider, no drugs
}
 
def build_targets(df):
    df = df.copy()
    for barrier_type, cols in BARRIER_COLS.items():
        present = [c for c in cols if c in df.columns]
        for c in present:
            df[f'{c}_bin'] = (df[c] == 'big problem').astype(int)
        df[f'target_{barrier_type}'] = df[[f'{c}_bin' for c in present]].max(axis=1)
        prevalence = df[f'target_{barrier_type}'].mean() * 100
        print(f'target_{barrier_type}: {prevalence:.1f}% positive  (built from {present})')
    drop_cols = [f'{c}_bin' for cols in BARRIER_COLS.values() for c in cols if f'{c}_bin' in df.columns]
    df = df.drop(columns=drop_cols)
    return df
EXPECTED CLASS BALANCE — NOT 50/50:
Based on the individual v467 prevalences already measured, expect roughly: Household ~30-35% positive, Logistic ~40-45% positive, Facility ~55-60% positive (OR-combining always pushes prevalence above the highest single component). All three are imbalanced. class_weight='balanced' or SMOTE is required again — the opposite of v4's guidance.

Step 2 — Handle Missing Values and DHS Special Codes
Unlike the district CSV (plain NaN only), the individual DHS file uses category-specific special codes for "don't know" / "not applicable" (commonly 8, 9, 98, 99, 999, 9998, 9999 depending on the variable). These must be converted to NaN before imputation — this step did not exist in v4 and must be restored from the original approach document's plan.
# src/preprocessing/clean.py
import numpy as np
 
SPECIAL_CODES = [8, 9, 98, 99, 998, 999, 9998, 9999]
 
def handle_missing(df, numeric_cols):
    df = df.copy()
    for col in numeric_cols:
        df[col] = df[col].replace(SPECIAL_CODES, np.nan)
    before = df[numeric_cols].isnull().sum().sum()
    for col in numeric_cols:
        if df[col].dtype.kind in 'if':
            df[col] = df[col].fillna(df[col].median())
        else:
            df[col] = df[col].fillna(df[col].mode()[0])
    after = df[numeric_cols].isnull().sum().sum()
    print(f'Missing before: {before}, after: {after}')
    return df

Step 6 — Train/Test Split, Class Imbalance, Scaling
With real class imbalance restored and 724,115 rows, the order of operations from the original approach document (Section 3.4) is back in force: split first, then SMOTE on the training fold only, then scale.
# src/preprocessing/split_scale.py
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from imblearn.over_sampling import SMOTE
 
def split_and_scale(df, target_col, use_smote=True, apply_scaling=True, sample_for_speed=None):
    feature_cols = [c for c in df.columns if not c.startswith('target_')]
    X, y = df[feature_cols], df[target_col]
    if sample_for_speed:
        # optional stratified subsample for fast GridSearchCV iteration — NOT for final fit
        X, _, y, _ = train_test_split(X, y, train_size=sample_for_speed, stratify=y, random_state=42)
    X_train, X_test, y_train, y_test = train_test_split(
        X, y, test_size=0.20, random_state=42, stratify=y)
    if use_smote:
        X_train, y_train = SMOTE(random_state=42).fit_resample(X_train, y_train)
    scaler = None
    if apply_scaling:
        scaler = StandardScaler()
        X_train = scaler.fit_transform(X_train)
        X_test = scaler.transform(X_test)
    print(f'{target_col} — Train: {len(y_train)} (post-SMOTE) | Test: {len(y_test)}')
    return X_train, X_test, y_train, y_test, scaler
COMPUTE NOTE:
SMOTE on ~580K training rows is expensive but tractable. If it becomes a bottleneck, prefer class_weight='balanced' (LR, DT, RF) or scale_pos_weight (XGBoost) over SMOTE — they achieve a similar effect without materialising synthetic rows across a 700K-row set. Use sample_for_speed (e.g. 50,000) only for GridSearchCV hyperparameter search, never for the final model fit.

SECTION 5  —  MODEL TRAINING — REBUILT HYPERPARAMETERS FOR N=724,115
5. Model Training — Implementation Details
WHY THE PARAMETERS BELOW DIFFER FROM v4:
v4's entire hyperparameter logic (max_depth=3-4, heavy L1/L2, GridSearchCV over the full grid on the full data) was reverse-engineered to prevent overfitting on 707 rows. from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV
 
def train_logistic(X_train, y_train, feature_names, target_name):
    param_grid = {'C': [0.1, 1.0, 10.0, 100.0]}
    base = LogisticRegression(solver='lbfgs', max_iter=1000, class_weight='balanced', random_state=42)
    grid = GridSearchCV(base, param_grid, cv=5, scoring='roc_auc', n_jobs=-1)
    grid.fit(X_train, y_train)
    model = grid.best_estimator_
    print(f'Best C for {target_name}: {grid.best_params_}')
    return model

from xgboost import XGBClassifier
 
def train_xgboost(X_train, y_train, target_name):
    neg, pos = (y_train == 0).sum(), (y_train == 1).sum()
    scale_pos_weight = neg / pos
    model = XGBClassifier(
        n_estimators=400, max_depth=6, learning_rate=0.08,
        subsample=0.8, colsample_bytree=0.8,
        scale_pos_weight=scale_pos_weight, tree_method='hist',
        eval_metric='auc', random_state=42)
    model.fit(X_train, y_train)
    return model
SECTION 6  —  MODEL EVALUATION
6. Evaluation — What Changes
Metric definitions (Accuracy, ROC-AUC, Precision, Recall, F1) are unchanged from v4. Two things change:
Accuracy is no longer a trustworthy headline number by itself — classes are imbalanced again, so a model predicting the majority class everywhere can still score well on accuracy. Lead with ROC-AUC and F1, exactly as the base paper does with its AOR + significance framing.
The hold-out test set is now ~145,000 rows instead of ~142. Single-split metrics are no longer noisy — 5-fold CV is still good practice for robustness, but v4's repeated warnings about CV being the primary measure because the hold-out set is "too small" no longer apply. Report the hold-out test score as the primary number; CV mean ± std as a stability check.

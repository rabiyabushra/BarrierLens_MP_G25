2.4  Understanding the Target Variables — How to Build Them
This is the most important section. Because the dataset does NOT contain individual barrier response columns (v467b–v467i), we cannot directly measure whether a district's women report barriers. Instead, we construct proxy-based binary targets: each barrier type is represented by 2–3 healthcare utilisation columns that are strongly theoretically linked to that barrier. We invert these columns (since low utilisation = high barrier), average them, and binarize at the district median.

2.4.2  How to Construct the 3 Binary Targets (in target_builder.py)
Strategy: For each barrier type, (1) select its proxy columns, (2) invert each column (100 - value, so LOW utilisation → HIGH score), (3) average the inverted scores into a single barrier score per district, (4) binarize at the district-level median — districts scoring above median are labelled 1 (HIGH BARRIER), others 0.
# ── src/preprocessing/target_builder.py ──
import pandas as pd
import numpy as np
def build_targets(df):
    '''
    Constructs 3 binary district-level barrier targets from healthcare
    utilisation proxy columns in the NFHS-5 district factsheet.
    Strategy: invert utilisation columns (low use = high barrier),
    average across proxies, binarize at district median.
    Returns df with target columns added; proxy columns dropped from features.
    '''
    df = df.copy()
    # ── TARGET 1: Household Barrier ──
    # Proxies: low insurance + low education → high financial/permission barriers
    hh_ins  = 'Households with any usual member covered under a health insurance/financing scheme (%)'
    hh_edu  = 'Women (age 15-49)  with 10 or more years of schooling (%)'
    df['_hh_score'] = ((100 - df[hh_ins]) + (100 - df[hh_edu])) / 2
    df['target_household'] = (df['_hh_score'] >= df['_hh_score'].median()).astype(int)
    # ── TARGET 2: Logistic Barrier ──
    # Proxies: low institutional births + low 4+ ANC visits → high distance/transport barriers
    lg_inst = 'Institutional births (in the 5 years before the survey) (%)'
    lg_anc  = 'Mothers who had at least 4 antenatal care visits  (for last birth in the 5 years before the survey) (%)'
    df['_lg_score'] = ((100 - df[lg_inst]) + (100 - df[lg_anc])) / 2
    df['target_logistic'] = (df['_lg_score'] >= df['_lg_score'].median()).astype(int)
    # ── TARGET 3: Facility-Level Barrier ──
    # Proxies: low skilled attendance + low vaccination + low postnatal care → high facility barriers
    fc_sba  = 'Births attended by skilled health personnel (in the 5 years before the survey)10 (%)'
    fc_vacc = 'Children age 12-23 months fully vaccinated (card or recall11) (%)'
    fc_pnc  = 'Mothers who received postnatal care from a doctor/nurse/LHV/ANM/midwife/other health personnel within 2 days of delivery (for last birth in the 5 years before the survey) (%)'
    df['_fc_score'] = ((100 - df[fc_sba]) + (100 - df[fc_vacc]) + (100 - df[fc_pnc])) / 3
    df['target_facility'] = (df['_fc_score'] >= df['_fc_score'].median()).astype(int)
    # Drop intermediate score columns and proxy columns (must NOT be input features)
    proxy_cols = [hh_ins, hh_edu, lg_inst, lg_anc, fc_sba, fc_vacc, fc_pnc,
                  '_hh_score', '_lg_score', '_fc_score']
    df = df.drop(columns=[c for c in proxy_cols if c in df.columns])
    return df
# Expected output distribution (district-level binarized at median):
# target_household:  ~50% positive  (by construction — median split)
# target_logistic:   ~50% positive  (by construction — median split)
# target_facility:   ~50% positive  (by construction — median split)
# NOTE: 50/50 split means NO class imbalance — SMOTE not required for these targets.
WHY MEDIAN-SPLIT BINARIZATION?
  The dataset has ~707 districts. Binarizing at the median gives a balanced 50/50 label split,
  which is ideal for classification. It also has a clear interpretation: districts in the top half
  of the barrier-score distribution are HIGH BARRIER districts. This is consistent with
  comparative district-level policy analysis — we are identifying which half of India's districts
  perform worse on each barrier dimension, not predicting an absolute threshold.

Step 2 — Handle Missing Values
This dataset uses standard NaN for missing values — no DHS special code conversion needed. A small number of cells may be missing where district-level data was not collected. Strategy: median imputation across all numeric feature columns. Do NOT impute identifier columns (District Names, State/UT).
# src/preprocessing/clean.py
import pandas as pd
import numpy as np
def handle_missing(df):
    df = df.copy()
    id_cols = ['District Names', 'State/UT']
    numeric_cols = [c for c in df.columns if c not in id_cols]
    before_nulls = df[numeric_cols].isnull().sum().sum()
    print(f'Total missing values before imputation: {before_nulls}')
    # Median imputation for all numeric feature columns
    for col in numeric_cols:
        if df[col].isnull().any():
            df[col] = df[col].fillna(df[col].median())
    after_nulls = df[numeric_cols].isnull().sum().sum()
    print(f'Total missing values after imputation: {after_nulls}')
    return df

# src/preprocessing/encode.py
import pandas as pd
def encode_features(df):
    df = df.copy()
    # Drop District Names — identifier only, not a feature
    if 'District Names' in df.columns:
        df = df.drop(columns=['District Names'])
    # One-hot encode State/UT (drop_first=True avoids dummy variable trap)
    if 'State/UT' in df.columns:
        df = pd.get_dummies(df, columns=['State/UT'], drop_first=True, dtype=int)
    return df
Step 6 — Train / Test Split + Feature Scaling
Important change from the original plan: SMOTE is NOT needed for this dataset. Because targets are binarized at the median, the class split is inherently 50/50 — there is no class imbalance. We apply only the train/test split and StandardScaler.
Operation
Details
Why This Order Matters
1. Train / Test Split (80 / 20)
stratified=True to preserve 50/50 class balance in both sets. With ~707 rows: ~565 train, ~142 test.
Must happen FIRST — test set must never be seen during any transformation.
2. NO SMOTE
Targets are 50/50 balanced by construction (median split). SMOTE would create unnecessary synthetic districts.
Applying SMOTE on balanced data can introduce noise without any benefit.
3. Z-score Scaling on X_train then X_test
StandardScaler fit on X_train only, then transform both X_train and X_test.
Fitting scaler on full data would leak test set statistics — a form of data leakage.
# src/preprocessing/split_scale.py
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
def split_and_scale(df, target_col, apply_scaling=True):
    '''
    Run this once per target (household, logistic, facility).
    Returns: X_train, X_test, y_train, y_test, scaler
    NOTE: No SMOTE — targets are balanced 50/50 by construction.
    '''
    feature_cols = [c for c in df.columns if not c.startswith('target_')]
    X = df[feature_cols]
    y = df[target_col]
    # Step 1: Train / Test Split (stratified for balanced classes)
    X_train, X_test, y_train, y_test = train_test_split(
        X, y, test_size=0.20, random_state=42, stratify=y
    )
    print(f'{target_col} — Train: {len(X_train)} rows | Test: {len(X_test)} rows')
    # Step 2: Z-score Scaling — fit on train, transform both
    scaler = None
    if apply_scaling:
        scaler = StandardScaler()
        X_train = scaler.fit_transform(X_train)
        X_test  = scaler.transform(X_test)   # .transform() — NOT .fit_transform()
    return X_train, X_test, y_train, y_test, scaler

4. Why Train 4 Different Models on the Same Dataset?
A common question from new team members: if XGBoost is the most powerful, why train the other three? The answer is that each model serves a distinct scientific and practical purpose. No single model is superior across all dimensions — performance, interpretability, comparability to the base paper, and policy communication each pull in different directions.

  • Without Decision Tree (RBM)         →  Cannot produce policy rules for non-technical decision makers.

  • Without XGBoost (Sharmila)          →  Miss the best-performing production model; lose Stage 2 accuracy.
Training all 4 also satisfies the systematic review finding of Badawy et al. [11] that ensemble
methods consistently outperform single estimators — we demonstrate this empirically by comparing
all 4 on the same dataset.

from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV
import joblib, numpy as np, pandas as pd
def train_logistic(X_train, y_train, feature_names, target_name):
    # Tune regularisation strength C on training data only
    param_grid = {'C': [0.01, 0.1, 1.0, 10.0]}
    base = LogisticRegression(solver='lbfgs', max_iter=500, random_state=42)
    grid = GridSearchCV(base, param_grid, cv=5, scoring='roc_auc')
    grid.fit(X_train, y_train)
    model = grid.best_estimator_
    print(f'Best C for {target_name}: {grid.best_params_}')
    joblib.dump(model, f'saved_models/stage1/logistic_regression_{target_name}.pkl')
    # Extract Odds Ratios for comparison with base paper AOR values
    coefs = pd.DataFrame({
        'Feature':    feature_names,
        'Coefficient': model.coef_[0],
        'OddsRatio':  np.exp(model.coef_[0])
    })
    print(coefs.sort_values('OddsRatio', ascending=False).head(10))
    return model

8. Cross-Validation Strategy
With only ~707 district rows, 5-fold stratified cross-validation is the PRIMARY performance measure for this project. The hold-out test set (~142 rows) is too small to give stable single-split metrics — individual folds may vary significantly. Always report CV mean ± std alongside the hold-out score.
from sklearn.model_selection import StratifiedKFold, cross_val_score
kf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
# Run CV for all 4 models on all 3 targets — use full X (before split) and full y
for model, name in [(lr_hh, 'LR'), (dt_hh, 'DT'), (rf_hh, 'RF'), (xgb_hh, 'XGB')]:
    scores = cross_val_score(model, X, y_household, cv=kf, scoring='roc_auc')
    print(f'{name} | Household | CV AUC: {scores.mean():.4f} +/- {scores.std():.4f}')
for model, name in [(lr_lg, 'LR'), (dt_lg, 'DT'), (rf_lg, 'RF'), (xgb_lg, 'XGB')]:
    scores = cross_val_score(model, X, y_logistic, cv=kf, scoring='roc_auc')
    print(f'{name} | Logistic  | CV AUC: {scores.mean():.4f} +/- {scores.std():.4f}')
for model, name in [(lr_fc, 'LR'), (dt_fc, 'DT'), (rf_fc, 'RF'), (xgb_fc, 'XGB')]:
    scores = cross_val_score(model, X, y_facility, cv=kf, scoring='roc_auc')
    print(f'{name} | Facility  | CV AUC: {scores.mean():.4f} +/- {scores.std():.4f}')
# Interpretation guide (for ~707-row district dataset):
# CV std < 0.05           → Model is STABLE on this dataset size
# CV std 0.05–0.08        → Acceptable variance for small dataset
# CV std > 0.08           → Model is UNSTABLE — try more regularisation
# CV mean >> test AUC     → Data leakage in preprocessing (re-check encode/scale steps)
# CV mean << test AUC     → Test split is unrepresentative (try different random_state)
